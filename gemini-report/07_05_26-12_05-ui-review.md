## 当前 UI 痛点分析

在保持了 macOS 原生白/黑系统主色和三栏布局的前提下，目前的 Web 实现可能存在以下导致“糟心”的原因：

1. **玻璃态 (Glassmorphism) 滥用与层次混乱**：
   - `.sidebar`, `.inspector`, `.metric-card`, `.panel` 都使用了 `backdrop-filter: blur` 和带透明度的背景色（例如 `rgba(255, 255, 255, 0.76)`）。
   - 在纯色背景（`#ffffff` 或 `#000000`）上大量使用模糊和透明面板，不仅没有透出底层内容的层次感（因为底层就是纯色），反而会让整体界面显得发灰、对比度不足、且视觉上显得杂乱和廉价。
2. **排版与字体对比度**：
   - 标题使用了 `Georgia, "New York"` 等衬线体，而界面信息又是紧凑的数据型呈现。对于一个需要快速扫视的 AI 监控数据大盘，衬线体有时显得过于传统，和原生工具属性产生割裂感。
   - 字体灰度（`--muted: #666666`, `--tertiary: #8a8a8f`）在半透明的面板上可能会出现对比度不达标（WCAG 访问性问题），导致信息难以阅读。
3. **空间与留白 (Spacing) 过于紧凑**：
   - 三栏布局把屏幕切得比较碎。中间的 `dashboard-grid` 和 `metrics-grid` 的间距（`gap: 10px` / `gap: 12px`）非常局促。过度的信息密度会让仪表盘显得拥挤压抑。
4. **色彩单调且缺乏引导**：
   - 根据 `DO_NOT_BREAK.md`，主色被严格限制为系统白/系统黑。界面除了状态色（ok, warn, bad）和一点系统蓝，缺乏引导视觉焦点的设计。导致用户第一眼无法分辨哪里是核心数据，哪里是辅助面板。

## 建议补丁方向（供 Codex 执行）

如果在不违反 `DO_NOT_BREAK.md` 中“只能用纯黑/纯白”和“保持 dashboard 而不是 landing page”的约束下，可以通过以下 CSS 和 HTML 结构调整来拯救 UI：

1. **克制玻璃态，回归实体面板**：
   - 建议仅在真正的浮层或侧边栏（如果背后有内容滚动穿过）使用 `backdrop-filter`。
   - 数据面板（`.metric-card`, `.panel`）应该使用坚实的背景色，通过轻微的阴影（如 `box-shadow`）和边框（`border`）来建立物理层次，避免全屏高斯模糊导致的廉价感。
2. **优化排版层级**：
   - 考虑将标题字体统一为 `var(--font-ui)`（非衬线体），通过不同的 `font-weight`（如 600, 700）和字号大小来建立清晰的信息层次结构，使数据图表类页面更具现代感和专业感。
3. **增加呼吸感 (Whitespace)**：
   - 稍微增加 `.metrics-grid` 和 `.dashboard-grid` 的间距（如加到 `16px` 或 `24px`），让面板之间有足够的物理区隔，减轻压迫感。
4. **局部微交互与质感提升**：
   - 增加悬浮交互的细节（例如卡片 `hover` 时阴影微调或边框高亮）。
   - 优化图表区域的空状态和占位符设计。
